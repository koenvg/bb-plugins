## Transport and packaging decisions

One PiBridgeChannel belongs to each PiRpcChild generation. It authenticates a single Unix-socket or Windows named-pipe connection with a random token, preserves bounded line framing, and closes with its child. The generated extension removes channel credentials from its environment after connection. The fork uses its own global channel symbol so resource/session replacement can reuse its socket without attaching stale listeners. Dynamic tool call IDs remain random and pending calls are rejected at session shutdown.

This replaces the file-descriptor/Bun reader workaround because the socket path is exercised by real pinned Pi 1.1.0 context replacement and reload tests under both Node and Bun. Session roots and BB_PI_SUBAGENTS_BRIDGE_SESSION_DIR are unchanged. Observation/capture, private commands, and speed guards remain in their fork-owned modules.

Portable spawn/kill and host execution use only public exports from the exact runtime SDK alias. Managed Pi installations offer self-update; Bun/npm installs retain their matching update commands. No update command is executed by preparation.

Structured error categories use upstream's classifier and locally retained explicit-message patterns from the pinned Pi 1.1.0 utilities. This avoids adding Pi's runtime dependency graph to production. The message-only overflow adapter is equivalent to the upstream synthetic assistant-error input, not the silent-overflow branch. Upstream literal error regressions and differential overflow tests cover this boundary. The original MIT license is included at vendor/pi-ai-LICENSE and as a legal comment on the adapted code. The source license was verified at Pi tag v1.1.0, commit abe508e1b89912adde45528136c3221eb69acdd7.

No dependency pins, dependency groups, engine ranges, generated speed archive, or compatibility workflow changed.
